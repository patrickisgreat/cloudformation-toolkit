# cloudformation-toolkit

A curated library of reusable, parameterized **CloudFormation templates** for
deploying more or less anything to AWS — containerised services, serverless APIs,
GraphQL, data lakes and ETL, databases, and self-hosted or managed model
inference. Set a handful of parameters and deploy.

Every template is standalone *and* nestable, documented with generated parameter
tables, and covered by an offline test suite that proves its secure defaults are
actually secure.

```bash
make install                                  # .venv with cfn-lint + pytest
make check                                    # lint + tests + docs + catalog
./bin/cfn list                                # what's in the library
./bin/cfn params containers/fargate-service   # what a template needs
./bin/cfn deploy container-service --env dev  # deploy a whole archetype
```

## Three layers

```
templates/     the library — one template, one job. Standalone and nestable.
stacks/        archetypes — a whole working system from a handful of parameters.
environments/  where and how to deploy: region, tags, naming, parameter sets.
```

You can enter at any layer. Deploy a single template with `cfn deploy
data/s3-bucket`, deploy a whole archetype with `cfn deploy container-service`, or
nest a template inside your own stack.

## The `cfn` CLI

One entrypoint, split by whether it needs an AWS account.

**Offline** — what CI runs, and what you run on a laptop with no credentials:

| Command | Does |
|---------|------|
| `cfn lint` | cfn-lint every template against the resource-provider schemas |
| `cfn test` | The offline test suite: conventions, security policy, per-template |
| `cfn check` | All of the above plus docs and catalog freshness |
| `cfn params <target>` | A template's parameters, grouped, required set first |
| `cfn list` | Every template and stack with its one-line description |
| `cfn docs` / `cfn catalog` | Regenerate the generated tables |
| `cfn new <group>/<name>` | Scaffold a template that is born tested |

**Online** — reads `environments/<env>/env.json` for region, tags, stack naming
and capabilities:

| Command | Does |
|---------|------|
| `cfn deploy <target> --env dev` | Package if needed, then create or update |
| `cfn diff <target> --env dev` | Build the change set, print it, discard it |
| `cfn outputs` / `events` / `drift` | Inspect a deployed stack |
| `cfn delete <target> --env dev` | Delete it, after asking |

## Testing without a `terraform test`

Terraform has `terraform test` with `mock_provider`. CloudFormation has no
equivalent, so this repo builds one. Three layers, all offline, no AWS account:

1. **`cfn-lint`** — the closest thing CloudFormation has to a compiler. Catches
   misspelled properties, wrong types, invalid enum values, bad `GetAtt` targets.
2. **`tests/`** — repo-wide sweeps. Structural conventions (every template has a
   README with generated tables, an example that would actually deploy, and a
   real test suite) and a **security policy baseline** with a justified-exemption
   ledger that fails the build on stale entries.
3. **`templates/*/*/tests/`** — per-template assertions, the direct analog of a
   `terraform test` suite: secure defaults, conditional wiring, pass-through,
   interface stability.

The policy rules resolve `Ref`s to parameter **defaults**, because the claim
being tested is "the defaults are safe". A caller who deliberately passes an
unsafe value is making an informed choice; a caller who passes nothing must land
somewhere defensible.

See [docs/TESTING.md](docs/TESTING.md).

# `data/efs-filesystem`

Encrypted EFS file system with per-subnet mount targets, a TLS-only file system
policy, lifecycle transition to Infrequent Access, and an optional POSIX access
point — the persistent volume for a container service whose tasks come and go.

## Usage

Deploy it directly:

```bash
./bin/cfn deploy data/efs-filesystem --env dev
```

Or nest it inside a stack:

```yaml
Resources:
  Data:
    Type: AWS::CloudFormation::Stack
    Properties:
      TemplateURL: ../../templates/data/efs-filesystem/template.yaml
      Parameters:
        NamePrefix: !Ref NamePrefix
        Environment: !Ref Environment
        VpcId: !GetAtt Network.Outputs.VpcId
        SubnetId1: !GetAtt Network.Outputs.PublicSubnet1Id
        ClientSecurityGroupId: !GetAtt Service.Outputs.SecurityGroupId
```

The decisions that matter:

- **Ingress is a security group, not a CIDR.** `ClientSecurityGroupId` is the
  only principal granted NFS; there is deliberately no way to open 2049 to a
  network range. Point it at the service's security group and membership in
  that group *is* the mount permission.
- **Mount targets cost nothing but placement matters.** One per AZ where
  clients run — a client in an AZ without one silently pays cross-AZ data
  charges. Subnets 2 and 3 are optional slots for exactly that reason; a
  scale-to-zero single-task service in one AZ needs only `SubnetId1`.
- **`ThroughputMode: bursting` is the cost-safe default.** It is included in
  the storage price. `elastic` bills every GB transferred and only pays off
  for spiky workloads that exhaust burst credits — check the metered rate
  before switching.
- **Backups default off** because backup storage bills monthly and this
  library defaults recurring costs to off. Turn `EnableAutomaticBackups` on
  the moment the volume holds anything you cannot regenerate.
- **The access point is how ECS should mount this.** It owns its directory
  (created on first mount, `0755`, owned by `PosixUid:PosixGid`) and pins every
  client to that identity, which sidesteps the classic root-squash/EACCES
  failure when a non-root container touches a fresh EFS. Wire
  `AccessPointId` into the task's volume configuration with
  `TransitEncryption: ENABLED` — the file system policy denies plaintext
  clients.

Failure mode to know: a task that mounts before the mount target's DNS
propagates fails with a timeout and ECS retries — first mount in a fresh VPC
can take a minute. If a mount fails with `EACCES`, the client bypassed the
access point; if with `ETIMEDOUT`, the client's security group is not the one
you granted.

See [`examples/basic`](examples/basic) for a parameter set you can deploy as-is.

### Parameters

| Parameter | Description | Type | Default |
|-----------|-------------|------|---------|
| `NamePrefix` | Prefix for every resource this stack names. Must be unique per account and region, since physical names collide across stacks. | `String` | **required** |
| `Environment` | Environment this stack belongs to. Used in names and tags.<br>Allowed: `dev`, `staging`, `prod` | `String` | `dev` |
| `VpcId` | VPC the mount targets and their security group live in. | `AWS::EC2::VPC::Id` | **required** |
| `SubnetId1` | Subnet for the first mount target. One mount target per AZ is enough — every client in that AZ mounts through it. | `AWS::EC2::Subnet::Id` | **required** |
| `SubnetId2` | Subnet for a second mount target, in a different AZ than the first. Leave empty for a single-AZ posture; a client task in an AZ with no mount target pays cross-AZ data charges and latency. | `String` | `""` |
| `SubnetId3` | Subnet for a third mount target. Leave empty when two AZs suffice. | `String` | `""` |
| `ClientSecurityGroupId` | Security group of the clients (ECS service, EC2 instances) allowed to mount this file system. NFS ingress is granted to this group and nothing else. | `AWS::EC2::SecurityGroup::Id` | **required** |
| `PerformanceMode` | generalPurpose fits almost everything. maxIO trades per-operation latency for aggregate throughput and cannot be changed after creation.<br>Allowed: `generalPurpose`, `maxIO` | `String` | `generalPurpose` |
| `ThroughputMode` | bursting is included in the storage price. elastic bills per GB transferred and suits spiky workloads that overrun their burst credits; watch the metered rates before choosing it.<br>Allowed: `bursting`, `elastic` | `String` | `bursting` |
| `TransitionToIA` | Move files not read for this many days to Infrequent Access storage, roughly a tenth of the standard price. NONE disables the transition.<br>Allowed: `NONE`, `AFTER_7_DAYS`, `AFTER_14_DAYS`, `AFTER_30_DAYS`, `AFTER_60_DAYS`, `AFTER_90_DAYS` | `String` | `AFTER_30_DAYS` |

| `AccessPointPath` | Directory the access point exposes as its root. Created on first mount, owned by the POSIX identity below. | `String` | `/data` |
| `PosixUid` | POSIX user id the access point enforces on every client. | `Number` | `1000` |
| `PosixGid` | POSIX group id the access point enforces on every client. | `Number` | `1000` |

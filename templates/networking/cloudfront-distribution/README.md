# `networking/cloudfront-distribution`

A CloudFront distribution with one origin: a private S3 bucket reached through
Origin Access Control, or any HTTPS custom origin (an ALB, an API). Viewers are
always redirected to HTTPS; with a custom domain the TLS floor is 1.2.

## Usage

Static site from a private bucket:

```bash
./bin/cfn deploy networking/cloudfront-distribution --env dev \
  --param OriginDomainName=my-bucket.s3.us-east-1.amazonaws.com \
  --param EnableSpaFallback=true
```

Or nested, wired to `data/s3-bucket` and `networking/acm-certificate`:

```yaml
Cdn:
  Type: AWS::CloudFormation::Stack
  Properties:
    TemplateURL: ../../templates/networking/cloudfront-distribution/template.yaml
    Parameters:
      NamePrefix: !Ref NamePrefix
      Environment: !Ref Environment
      OriginDomainName: !GetAtt AssetsBucket.Outputs.RegionalDomainName
      AlternateDomainNames: www.example.com
      CertificateArn: !GetAtt Certificate.Outputs.CertificateArn
```

## The bucket policy is the caller's half of OAC

With `OriginType: s3` the distribution *signs* its requests, but the bucket
still has to let it in. Add this statement to the origin bucket's policy, using
the `DistributionArn` output — without it every request returns 403:

```json
{
  "Effect": "Allow",
  "Principal": { "Service": "cloudfront.amazonaws.com" },
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::my-bucket/*",
  "Condition": { "StringEquals": { "AWS:SourceArn": "<DistributionArn>" } }
}
```

The `AWS:SourceArn` condition is what stops a *different* account's
distribution from naming your bucket as its origin (the confused-deputy case).

## Fronting an API instead of a bucket

Three parameters change, and each default is wrong for an API if left alone:

| Parameter | Set to | Because |
|-----------|--------|---------|
| `OriginType` | `custom` | The origin speaks HTTPS, not sigv4 |
| `CachePolicyId` | `4135ea2d-6df8-44a3-9df3-4b5a84be39ad` (CachingDisabled) | Caching an authenticated response and serving it to the next caller is the classic CDN incident |
| `OriginRequestPolicyId` | `b689b0a8-53d0-40ab-baf2-68738e2966ac` (AllViewerExceptHostHeader) | Otherwise query strings, cookies and Authorization headers never reach the origin |

Also clear `DefaultRootObject` — for an API, `/` is a real route.

## Everything us-east-1

The certificate (`AlternateDomainNames` + `CertificateArn`) and the WAF web ACL
(`WebAclArn`) must both live in **us-east-1**, wherever the rest of the stack
is. The wrong region fails at deploy with an error that reads like the ARN is
invalid. `networking/acm-certificate` deployed into us-east-1 produces the
right certificate; aliases and certificate are applied only as a pair, so
setting one without the other quietly falls back to `*.cloudfront.net` rather
than failing the deploy.

## The cost knob

`PriceClass_100` (the default) serves from North America and Europe.
`PriceClass_All` adds the most expensive edges and raises the per-GB rate for
traffic from them. Viewers outside the class are still served — from a farther
edge with higher latency — so widen it when latency in Asia or South America
matters, not before.

## SPA fallback rewrites 403, on purpose

A private S3 origin answers 403 (not 404) for a missing key, because `ListBucket`
is not granted. `EnableSpaFallback` therefore rewrites both 403 and 404 to
`/index.html` with a 200. Do not enable it for anything that is not an SPA: it
turns every broken asset link into a soft 200 of your index page.

Deploys of new content need an invalidation
(`aws cloudfront create-invalidation --distribution-id <DistributionId> --paths "/*"`)
or content-hashed filenames — the latter is free, the former is not after the
first 1,000 paths each month.

See [`examples/basic`](examples/basic) for a parameter set you can deploy as-is.

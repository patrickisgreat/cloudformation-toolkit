# foundation/access-analyzer

The audit half of managing IAM in this library: `foundation/iam-role`,
`iam-groups`, and `iam-user` decide who *should* have access; this template
watches what *actually* has access. The external-access analyzer flags any
resource — bucket, key, role trust policy, secret — reachable from outside
the account (or organization), continuously, for free.

## The decisions that matter

**The free analyzer is unconditional; the paid one is opt-in.** Unused-access
analysis (which roles and permissions nobody has exercised in
`UnusedAccessAgeDays`) costs roughly $0.20 per IAM role or user analyzed per
month — trivial for ten roles, real money for a thousand. Turn it on when you
actually review its findings; it is the tool that tells you which
`iam-groups` tier assignments were too generous.

**Scope follows your account model.** With one account, the default
`account` scope is right. Once `foundation/org-account` gives you several,
switch to `organization` — one analyzer in the management account (or a
delegated admin) covers every member account, including ones vended later.
Deploying `organization` scope from a member account fails with
`AccessDeniedException`; that is the analyzer telling you where it belongs.

**An analyzer with unread findings is a dashboard, not a control.** Findings
land in the console and EventBridge (`aws.access-analyzer` events). Wiring
them to a notification is what turns "we have Access Analyzer" into "we knew
within an hour" — `messaging/sns-topic` plus an EventBridge rule is the
missing piece this library does not model yet.

## Usage

```bash
./bin/cfn deploy foundation/access-analyzer --env prod
```

Findings appear under IAM → Access Analyzer in the console within about 30
minutes of the first deploy. Review them once, archive the intentional ones,
and from then on a new finding means something actually changed.

### Parameters

| Parameter | Description | Type | Default |
|-----------|-------------|------|---------|
| `NamePrefix` | Prefix for the analyzer names. | `String` | **required** |
| `AnalyzerScope` | "account" analyzes this account; "organization" analyzes every member account, and only works from the management account or a delegated Access Analyzer administrator. If you vend accounts with foundation/org-account, one organization-scoped analyzer beats one stack per account.<br>Allowed: `account`, `organization` | `String` | `account` |
| `EnableUnusedAccessAnalyzer` | Also create an unused-access analyzer, which flags roles, keys, and permissions nobody has exercised. Off by default because it is the paid half: roughly $0.20 per IAM role or user analyzed per month.<br>Allowed: `true`, `false` | `String` | `false` |
| `UnusedAccessAgeDays` | Days without use before access counts as unused. 90 tracks the common compliance definition; shorter is noisier, not stricter. | `Number` | `90` |

# Template conventions

These keep the library consistent enough to compose. Most of them are enforced by
`tests/test_conventions.py`, so a conventions doc that drifts from reality fails
the build rather than misleading someone.

## Directory shape

Every template lives at `templates/<group>/<name>/` and contains:

| File | Purpose |
|------|---------|
| `template.yaml` | The template. One job. |
| `metadata.yaml` | Catalog entry: `group`, `status`, one-line `summary`. |
| `README.md` | Hand-written decisions + generated tables between `<!-- BEGIN_CFN_DOCS -->` markers. |
| `examples/basic/parameters.json` | A parameter set that would actually deploy. |
| `tests/test_<name>.py` | At least three tests. An empty suite reads as coverage. |

Stacks under `stacks/<name>/` follow the same shape and are held to the same
rules — a composition layer that is exempt from the conventions is the layer that
rots.

## The shared parameter interface

Composition only works if the shapes line up.

**`NamePrefix`** — required on every template, with an `AllowedPattern`. Every
physical name derives from it. Without it, two stacks of the same template in one
account collide on every name they create; with it, a stack passes its own prefix
straight down to its children.

**`Environment`** — `dev` | `staging` | `prod`, defaulting to `dev`, used in
names and injected into containers as `ENVIRONMENT`.

One template deliberately breaks this: `containers/ecr-repository` has **no**
`Environment`, because an image is built once and promoted rather than rebuilt
per environment. The test that enforces the absence explains why.

**Suffix parameters** (`ServiceSuffix`, `BucketSuffix`, `QueueSuffix`) let one
prefix carry several instances of a thing.

## Secure by default, and provably so

The default parameter set must produce the safe configuration. Not the cheapest,
not the most convenient — the one you would defend in review.

`tests/test_policy.py` enforces this across every template: encryption declared,
public access blocked, TLS-only bucket policies, log retention set, stateful
resources retained, no wildcard IAM on wildcard resources, no hardcoded account
IDs, secret-shaped parameters marked `NoEcho`.

The rules resolve `Ref`s to parameter **defaults**, because that is exactly the
claim: a caller who passes nothing lands somewhere defensible.

Anything a rule flags gets fixed or gets an entry in
`tests/policy_exemptions.yaml` with a written justification. A stale exemption
fails the build, so the ledger cannot quietly accumulate.

## Anything with a recurring cost is opt-in

The cost of a default is paid by everyone who does not think about it. So:
Fargate Spot off, interface endpoints off, enhanced fan-out off, flow logs off,
Glue jobs off, provisioned concurrency off — and the *free* things (gateway
endpoints, encryption, long polling) on.

Where a cost is unavoidable, the parameter description says roughly what it is.
`NatGatewayMode` in `foundation/vpc` has a table.

## Escape hatches over exhaustive modelling

Prefer a small number of high-level knobs plus one raw passthrough over a
parameter per nested attribute. `ecr-repository` has `KeepLastNImages` and
`ExpireUntaggedAfterDays` — and `LifecyclePolicyText` for the rules those two
cannot express.

## Naming

- Logical IDs are `PascalCase` and alphanumeric (CloudFormation requires it).
- The single primary resource of a template is named for what it is —
  `Bucket`, `Cluster`, `Queue` — not `MyBucket` or `Bucket1`.
- Parameters and outputs are `PascalCase`.
- Conditions read as predicates: `HasNat`, `IsProvisioned`, `ShouldCreateCrawler`.

## Tagging is mostly not in the template

`bin/cfn deploy` applies stack-level tags, and CloudFormation propagates them to
every resource type that supports tagging. Templates tag inline only where the
stack cannot: a `Name` tag, or a tag another service keys off (the
`kubernetes.io/role/elb` subnet tags).

## Outputs are the API

Expose the identifiers a caller needs to wire this to something else — names,
ARNs, URLs, IDs, and both halves of anything that comes in pairs (a Route 53
alias needs a DNS name *and* a hosted zone ID; request-based autoscaling needs a
load balancer full name *and* a target group full name).

Do not echo back inputs the caller already has. Every output needs a
`Description`; it appears in the console and in the generated table.

An output referencing a conditional resource must carry the same `Condition`.

## Documentation

The parameter, output and resource tables are generated by `./bin/cfn docs`
between the `<!-- BEGIN_CFN_DOCS -->` markers. Never hand-edit them — CI fails on
drift, because a parameter table that disagrees with the template is worse than
none.

The hand-written part above the markers should answer *which knobs matter and
why*, not repeat what the table already says. Good sections to include: the
decision that costs money, the default that will surprise someone, the failure
mode and what it looks like.

## Status levels

| Status | Means |
|--------|-------|
| `stable` | Lints clean, tested, docs describe reality, the shape is not expected to change |
| `beta` | Correct as far as it goes, with a known limitation stated in the README |
| `experimental` | Shape may change; do not depend on the interface |

`beta` is not a hedge. `serverless/appsync-graphql` is beta because AppSync's
per-field resolver model does not fit a fixed-shape template, and the README says
so; `ml/gpu-inference-service` is beta because GPU serving has many moving parts
and it has not been exercised across every instance family.
